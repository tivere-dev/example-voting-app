## Summary of what the output above shows
- Section 1: an existing cluster (node UID 3c202937..., created 09:02:59 UTC) with
  Helm release revision 4 and 5 votes.
- Section 2: `down --yes` deleted only the "capstone" profile in 11 s. The
  separate "minikube" profile is still listed and was not started or changed.
- Section 3: `up` recreated everything from the repository in 157 s: Minikube
  profile, images built from commit e5f6023, images loaded, and a fresh Helm
  install (revision 1) with all five pods ready.
- Section 4: a new node (UID dddfe14f..., created 10:02:42 UTC) and an empty
  database, then a passing smoke test. Old votes are gone because the whole
  cluster, including its volume, was deleted. This is expected.

Limitation: this demonstrates rebuilding a LOCAL Minikube environment from
code. It does not demonstrate the brief's AWS EKS cluster in the default VPC;
terraform/ has never been applied.
