## Summary of what the output above shows
- Revision 1 (install) was healthy.
- Revision 2 changed only vote.image.tag to "does-not-exist". The new vote pod
  could not pull its image (ErrImagePull / ImagePullBackOff), so it never became
  ready. Helm waited 90 s (--wait) and marked revision 2 "failed" (exit code 1).
- Because the vote Deployment uses maxUnavailable: 0, the old vote pod was never
  removed. The vote Service kept routing only to the ready old pod, and every
  availability check during the bad release returned HTTP 200 (section 4).
- `helm rollback voting-app 1` created revision 3 ("Rollback to 1"). The stuck
  pod was removed, the original pod kept serving, and the smoke test passed.
